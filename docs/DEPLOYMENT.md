# Deployment guide

The app runs as three pieces:

| Piece | Host | What it is |
| --- | --- | --- |
| API | Render (free web service) | Express app in `server/` |
| Client | Vercel (Hobby plan) | Vite build of `client/` |
| Database | MongoDB Atlas (free M0 cluster) | Users, plans, tasks, quizzes, flashcards |

The repository has `render.yaml` for the API and `client/vercel.json` for the client, so both hosts can be configured from files. The steps below also cover the manual path.

## 1. Create the MongoDB Atlas cluster

1. Sign in at https://cloud.mongodb.com and create a project.
2. Create a free M0 cluster. Any provider and region is fine. Pick a region close to your Render region.
3. Under **Database Access**, add a database user with a username and a strong password. Use the built-in role **Read and write to any database**.
4. Under **Network Access**, add an IP access rule. Render's free tier has no fixed outbound IPs, so add `0.0.0.0/0` and rely on the database user password. Atlas warns that this is open to the internet. That is expected for a free host with dynamic egress.
5. Copy the connection string from **Connect > Drivers**. It looks like `mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority`.
6. Add the database name `studybuddy` after the host and before the query string: `mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/studybuddy?retryWrites=true&w=majority`.
7. If your password contains `@`, `:`, `/` or `?`, URL-encode those characters.

That string is the `MONGODB_URI` value for Render.

## 2. Deploy the API on Render

### Blueprint path

1. Push the repository to GitHub.
2. In the Render dashboard, choose **New > Blueprint** and select the repository.
3. Render reads `render.yaml` and creates the `studybuddy-api` web service with `rootDir: server`, `buildCommand: npm ci` and `startCommand: npm start`.
4. Fill in the variables marked as secrets:
   - `MONGODB_URI`: the Atlas string from step 1.
   - `GROQ_API_KEY`: from https://console.groq.com/keys.
   - `GEMINI_API_KEY`: from https://aistudio.google.com/apikey. Optional, but it enables the backup provider.
   - `CLIENT_URL`: set this after the Vercel deploy, see step 4.
5. `JWT_SECRET` is generated by Render. Keep it secret and do not reuse it elsewhere.
6. Apply the blueprint. The first deploy fails the health check until `CLIENT_URL` is a valid origin, so use a placeholder such as `https://example.com` on the first pass, then replace it in step 4.

### Manual path

Create a **Web Service** instead of a Blueprint and use these settings:

| Setting | Value |
| --- | --- |
| Root directory | `server` |
| Runtime | Node |
| Build command | `npm ci` |
| Start command | `npm start` |
| Health check path | `/api/health` |
| Instance type | Free |

Then add the variables from the table in step 3.

Render injects `PORT`. Do not set it yourself, and do not set it to a fixed value.

## 3. Deploy the client on Vercel

1. In Vercel, choose **Add New > Project** and import the same repository.
2. Set **Root Directory** to `client`. Vercel picks up `client/vercel.json`, which sets the Vite framework, `npm run build`, `dist` as the output, and a catch-all rewrite so client-side routes such as `/dashboard` and `/plans/:id` load `index.html` instead of a 404.
3. Add one environment variable for the Production environment:
   - `VITE_API_URL`: the Render service URL, for example `https://studybuddy-api.onrender.com`. No `/api` suffix and no trailing slash. The client appends `/api`.
4. Deploy. Vite reads `VITE_API_URL` at build time, so changing it needs a new deployment.

## 4. Connect the two with CORS

The API only accepts browser requests from the exact origins listed in `CLIENT_URL`. There are no wildcards and no paths.

1. Copy the Vercel production URL, for example `https://studybuddy-planner.vercel.app`.
2. In Render, open the `studybuddy-api` service, then **Environment**, and set `CLIENT_URL` to that origin.
3. Save. Render restarts the service.
4. Reload the Vercel site and sign in. If the browser console shows `Origin not allowed`, the value in `CLIENT_URL` does not match the page origin exactly.

Notes:

- Use `https`, not `http`.
- Multiple origins are allowed, comma separated, for example a custom domain plus the `vercel.app` domain: `https://studybuddy.app,https://studybuddy-planner.vercel.app`.
- Do not add a trailing slash. A URL with a path is rejected at startup.
- Vercel preview deployments get a new random origin per deployment. Add one preview origin temporarily if you need to test, then remove it.

## 5. Environment variables

Set these on Render, not in the repository. `server/.env.example` lists the same names.

| Variable | Required | Value |
| --- | --- | --- |
| `NODE_ENV` | yes | `production` |
| `MONGODB_URI` | yes | Atlas connection string with the database name |
| `JWT_SECRET` | yes | at least 32 characters, generated by Render in the blueprint |
| `CLIENT_URL` | yes | exact Vercel origin, comma separated if more than one |
| `AI_PROVIDER` | no | `groq` |
| `GROQ_API_KEY` | yes when `AI_PROVIDER` is `groq` | Groq API key |
| `GROQ_MODEL` | no | `openai/gpt-oss-120b` |
| `GEMINI_API_KEY` | no | enables the backup provider |
| `GEMINI_MODEL` | no | `gemini-3.8-flash` |
| `GEMINI_FALLBACK_MODEL` | no | `gemini-3.5-flash` |
| `AI_DAILY_LIMIT` | no | `15` |
| `PORT` | no | injected by Render, do not set |

Startup fails with a clear message and a non-zero exit code when a required variable is missing, when `JWT_SECRET` is shorter than 32 characters, when `CLIENT_URL` contains a wildcard or path, or when no AI provider key is set.

On Vercel, the only variable is `VITE_API_URL` and it must exist in the environment you deploy (Production, Preview or Development).

## 6. Verify the deployment

1. Open `https://YOUR-SERVICE.onrender.com/api/health`. It must return `{"status":"ok"}`.
2. Open the Vercel URL. The landing page must load with no console errors.
3. Register an account, create a plan with three or four topics and an exam date about a week out. Plan generation takes a few seconds on a warm service.
4. Toggle a task, reload, and confirm the change persists. That proves the Atlas write path.
5. Check the Render logs for the request lines. A 403 with `Origin not allowed` means `CLIENT_URL` is wrong.
6. On Render, confirm the service health check shows **Live**, not **Failed**.

## 7. Free tier behaviour

- The Render free web service spins down after about 15 minutes without traffic. The next request wakes it and can take 30 to 60 seconds. A cold start plus plan generation can take over a minute, so the first plan after idle may feel slow. It is not a failure.
- Render free services have 512 MB of RAM. The API is small, so this is enough.
- The free Render plan has no fixed outbound IPs, which is why Atlas network access uses `0.0.0.0/0`.
- Atlas M0 has a 512 MB storage limit. Quiz and flashcard decks are small, so this is enough for a demo.
- Groq's free tier is limited to 8K tokens per minute. The API sends one provider request at a time with a small output cap, so a single user stays inside that limit. Several users generating at once will queue.
- `AI_DAILY_LIMIT` and the per-user limiter counters live in memory. A Render restart, deploy or spin down clears them.

## 8. Redeploying

- Render redeploys on every push to `main` because `render.yaml` sets `autoDeployTrigger: commit`.
- Vercel redeploys on every push to the production branch.
- Changing an environment variable requires a manual redeploy on Vercel, because Vite inlines `VITE_API_URL` at build time. Render restarts automatically on save.
